# Long Beach baseline audit

Research date: 2026-10-28. Decision context: [Audit the Long Beach baseline and identify reusable strengths](https://github.com/robcdownie/Orlando-2026/issues/2).

Source pinned to [`71f1bc956becbd4a045f7feb69727a02521f2037`](https://github.com/robcdownie/warpedLB/tree/71f1bc956becbd4a045f7feb69727a02521f2037). This is a source-and-test-inventory audit, not a runtime certification. No app code changed; no unit, browser, installed-phone, or production tests were executed in this investigation. README claims are separated from implementation evidence below. Global memory recall by the coordinating session found no relevant context; project memory was unavailable. No durable memory written.

## Finding

Warped LB is substantially more than a static lineup or map. Its domain logic, explicit uncertainty states, independent personal selections, local storage, and import validation are strong reuse candidates. Orlando should improve data distribution, actual offline assurance, map calibration, and the primary phone journeys before considering a full rewrite. This is a recommendation for the subsequent product/architecture decisions, not approval of a particular stack or scope.

## Concrete risks and improvements

1. **Offline readiness is weaker than an actual reopen proof.** `runOfflineTests` passes the service-worker check when a registration is active even when it is not controlling the page. Its shell check accepts any matching HTML, JS, or CSS entry, rather than verifying the entire current dependency set. “Can reopen offline” tests existence of a cached base URL; it does not execute an offline cold start. This is directly observed code; the inference is that incomplete or mismatched caches could pass checks that sound stronger than their evidence. Recommend required-asset/version validation plus a real offline reload/cold-start acceptance procedure. [Offline checks](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/offlineTests.ts).

2. **Import/restore is not one atomic multi-store change.** The implementation snapshots first, then performs separate awaited repository writes and clears. The repository gives individual stores their own transactions. A snapshot supports recovery, but does not make the whole operation atomic. Interrupted restore/import could therefore leave a partial state; this is a source-derived failure risk, not a reproduced defect. Recommend a multi-store transaction or explicit resumable/recoverable commit protocol, with interruption tests. [Import/rollback](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/share/importCommit.ts), [repository transactions](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/db/repo.ts).

3. **Map distance is festival-specific estimation, not pedestrian routing.** `travel.ts` hard-codes the LB artwork aspect ratio, a tuned distance-to-minutes factor, and crowd multipliers, with pair overrides. Orlando's screenshot cannot safely inherit those constants. Recommend a distinct Orlando calibration and explicit uncertainty; route-aware estimates require evidence of traversable paths and boundaries. [Travel model](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/travel.ts).

4. **Clash coverage excludes non-main performances.** `detectConflicts` filters to `perf.type === 'main'`, as does day completeness. Orlando must decide whether unplugged or other appearances are part of “my sets” and avoid silently omitting them. This is an observed boundary, not automatically a defect in LB's chosen scope. [Conflict filter](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/conflicts.ts), [completeness filter](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/scheduleStatus.ts).

5. **Public timetable distribution needs an explicit owner and freshness policy.** LB documents human-entered times and deliberate code exchange. Schedule-import code records source, imported/exported timestamps and revision, but this is not an official live feed. Orlando should decide whether to retain codes, publish curated updates, or combine both. No evidence here establishes an available official API. [Baseline data instructions](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/README.md), [import provenance](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/domain/share/importCommit.ts).

6. **Porting requires more than replacing a logo.** Dates, timezone, entrance ID, venue, map image, seed data, base URL, manifest scope, cache names, and database names encode LB assumptions. Use an Orlando event identity and check same-origin isolation if both apps are hosted under one domain. [Event configuration](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/config/event.ts), [PWA config](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/vite.config.ts), [database names](https://github.com/robcdownie/warpedLB/blob/71f1bc956becbd4a045f7feb69727a02521f2037/src/db/schema.ts).

## Options for the decision session

- **Recommended investigation path: reuse domain/storage foundations, redesign selected journeys.** Preserves prior edge-case work while concentrating the short delivery window on credible offline readiness, trustworthy public updates, and Orlando-specific map/data handling.
- **Fork and reskin the whole app.** Lowest initial integration work, but carries many LB assumptions and existing interaction complexity. Require an explicit migration inventory and regression gates.
- **Rewrite from scratch.** Justifiable only if research/prototypes expose constraints the baseline cannot meet; otherwise recreates substantial tested logic before a fixed festival deadline.

Remain unresolved: actual user pain and preferred flows; current production/CI health; physical-device cold starts, storage eviction and upgrade behavior; accessibility/contrast/touch-target audit; Orlando data authority and map provenance; policies for friends, accounts, non-main appearances, and automatic updates. These are downstream decisions/validation, not reasons to represent the source audit as runtime proof.
