# Montréal companion: ideas and architecture cautions for Orlando

Research for [Choose the offline architecture and code reuse strategy](https://github.com/robcdownie/Orlando-2026/issues/7). Inspected October 31, 2026. Candidate project: [Warped MTL Companion](https://github.com/robcdownie/warpedmtl/tree/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac), a Montréal, Québec festival companion. Confirm with Robbie if he meant a different Québec project. This is a source and documentation review at commit `a31d4daa670a47fd616d72d28ebe1f8693d8c2ac`; it is not evidence the app was used at the festival, deployed successfully, or verified on a phone. No tests were run.

## Useful ideas

- The [README](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/README.md) describes a local-first Vite, React, TypeScript, IndexedDB and Workbox application with deliberate offline friend-code exchange, local backup and map features. This is a candidate source of implementation ideas, not proof of Orlando readiness. It explicitly warns that iPhone Safari and the installed Home Screen app have separate storage and instructs opening the installed app online. Orlando should test and explain migration of an existing plan and offline preparation between contexts rather than imply automatic transfer.
- [Trust-state documentation](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/docs/trust-states.md) describes useful distinctions for group features: a friend whose plan has not arrived is unknown rather than free; a stale check-in is historical rather than a current position; a cached map is not necessarily verified; and an estimated end should remain visibly estimated. Stage now/next with qualified estimates is an interaction idea for the phone-review ticket. These are source/documented design claims, not verified outcomes.
- [Lineup migration code](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/src/data/lineupMigrations.ts) models versioned corrections and notices, including carrying saved selections and marking cancellations. The revisions list is empty at the inspected commit. Consider the notice and preservation ideas, while following Orlando's approved explicit-update, stable-appearance and personal-edit reconciliation contract rather than importing this behavior unchanged.
- The [codec](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/src/domain/share/codec.ts) encodes event identity, payload type and version in compressed self-contained text. Its CRC32 checks accidental corruption, not publisher authenticity; it cannot by itself support Orlando's approved-publisher claim. Actual code sizes, QR chunking and phone compatibility need measurement against Orlando data.

## Risks to address before reuse

- [Offline readiness source](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/src/domain/offlineTests.ts) marks service worker active even when it is not controlling; the shell test accepts any matching HTML, JS or CSS; and the reopen check looks for a cached start URL. These checks do not prove a complete, usable offline cold start. Its [device checklist](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/docs/offline-testing.md) is useful as a test idea, but still refers to Long Beach-specific seed counts, so documentation cannot be treated as current Montréal evidence.
- The [import and rollback implementation](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/src/domain/share/importCommit.ts) saves a pre-import snapshot and then performs multiple awaited writes and clears. A snapshot is a recovery aid, not evidence that the full import or rollback commits atomically. Orlando must verify interruption, quota failure and recovery without rolling back newer personal choices.
- [Event configuration](https://github.com/robcdownie/warpedmtl/blob/a31d4daa670a47fd616d72d28ebe1f8693d8c2ac/src/config/event.ts) explicitly retains legacy day IDs whose displayed weekdays differ. Treat identifiers, event isolation, date/timezone, map coordinates and assumptions as migration work; do not copy them blindly.

## Decision implication

The Montréal project reinforces selective reuse of existing local-first foundations and concrete trust-state ideas. It does not change the prior Orlando decisions about anonymous use, self-contained offline timetable transfer, verified publisher identity, independent map readiness, or preservation of personal choices. It does not establish that these behaviors have passed Orlando's release gates. Recheck the relevant source and test behavior during implementation.
